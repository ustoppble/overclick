chapter 01 of 08 · install and first run

Two commands and the board is yours

Nothing here calls out of your machine. Postgres ships in the compose file, the admin account lives in your own database, and the board never phones home: no analytics, no verification e-mail, no telemetry.

01 · what you need

Requirements

Docker and Docker Compose, and an MCP-capable coding agent on the same machine you work on: Claude Code, Codex CLI, Gemini CLI, Overclock, or any MCP client. That is the whole list. There is no account to create anywhere, and no cloud tier.

  • macOS: brew install --cask docker && open -a Docker (OrbStack works too)
  • Linux: your distro's docker plus the docker-compose-plugin package
  • Windows: Docker Desktop with the WSL2 backend
02 · run it

Clone and bring it up

$ git clone https://github.com/ustoppble/overclick && cd overclick $ docker compose up --build # → http://localhost:3000

The first build takes a couple of minutes; after that it is seconds. When the log settles, open http://localhost:3000.

Exposing it on a server? Set AUTH_SECRET to your own value of 32 characters or more in the compose environment before anyone else can reach it. The default is for local use only. Either way, nothing in the app calls out of your server.
03 · your account

Create the admin account

First access shows the setup screen: your e-mail, then the 6-digit code sent to it. There is no password; the code is how you sign in, every time. No marketing questions. It is a login, and it exists so a browser session can prove it is you before validating an agent's work. Codes go out through Resend; without it, an emergency link made on the server (pnpm emergency-login) creates the first admin and signs you in once.

04 · onboarding

Three steps, then the board is live

Step 1 · Project

Name it, and optionally paste the repository URL. The board derives an ID prefix from the name (Agent Board becomes AB), and that prefix drives the whole Git convention: cards are born as AB-1, branches as ab-1-fix-login, and commits and pull requests carry the same id. One project maps to one repository; you can add more later.

Step 2 · Executors

Check the CLIs and models your team actually has. This is not a wish list: it is what the board is allowed to recommend. A model nobody owns will never show up on a card. Chapter 4 turns this list into a policy.

Step 3 · Connect your agent

Two paths, both ending with an agent connected over MCP. The recommended one is the pairing code, and it is chapter 2. Finish the wizard even if you stop here: the board is already usable, and Settings has the same buttons.

05 · what you should see

A board with one card on it

A fresh instance is born with a single example card, AGB-1, titled something like "Ask your agent to grab this task". It sits in Open with a recommended harness under the title. That card is the target of chapter 2: you will not touch it with the mouse again.

Everything you just created is in your Postgres, on your disk. Dump it, back it up, move it to another machine: it is yours, and the board has no opinion about where it runs.

06 · when it does not come up

Two failures worth naming

SymptomWhat to check
Port 3000 is taken Something else is already serving it. Stop that process, or change the published port in docker-compose.yml and use the new one everywhere in this course.
The app starts before Postgres is ready Rare, and it fixes itself: docker compose up again. The migrations are idempotent, so a second run costs nothing.

Chapter checklist

  • Docker is running and docker compose up --build finished without errors
  • http://localhost:3000 opens the board
  • The admin account exists and you can sign back in after a reload
  • A project exists and you know its ID prefix
  • The executors you actually own are checked
  • The example card is sitting in the Open column
